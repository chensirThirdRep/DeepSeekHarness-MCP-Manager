# skill-management Specification

## Purpose
技能管理页必须列出运行时可见的技能，并包含 DSH 主目录下的用户级技能。用户的技能根目录位置不随 DSH 版本改变，插件不得因运行时文档语义变化而扫错目录。

## Requirements

### Requirement: 用户级技能发现

技能列表 MUST 合并运行时技能快照与 DSH 主目录下技能目录中的用户级技能；目录形态（子目录内的 \`SKILL.md\`）与扁平形态（根目录下的 \`*.md\`）MUST 都被识别。

#### Scenario: 用户级技能出现在列表中

- **WHEN** DSH 主目录下的技能目录中存在 2 个用户级技能，且运行时快照未包含它们
- **THEN** 列表包含这 2 个技能，其来源标记为用户级

#### Scenario: 不因活动 profile 改变而丢失

- **WHEN** 活动 profile 不是 \`web\`（例如 \`mcpman-dev\` 或 \`desktop\`）
- **THEN** 用户级技能仍能被发现，且列表内容与 profile 名无关

#### Scenario: 主目录未知时不报错

- **WHEN** DSH 主目录无法确定
- **THEN** 技能列表仍返回运行时快照中的技能，且不抛出异常

### Requirement: 用户级技能只读

用户级技能 MUST 只支持查看；对用户级技能执行启用或停用 MUST 被拒绝并返回明确原因，MUST NOT 改写该技能文件。

#### Scenario: 拒绝切换用户级技能

- **WHEN** 对用户级技能请求停用
- **THEN** 返回失败结果，错误信息说明用户级技能由 DSH 文件系统管理、需要直接编辑文件
- **AND** 该技能的 \`SKILL.md\` 内容保持不变

### Requirement: 技能启停持久化

对非用户级技能的停用 MUST 被持久化，使之后的技能列表与运行时会话仍然看到停用状态；重新启用后 MUST 恢复为原始定义。

#### Scenario: 停用后仍然停用

- **WHEN** 停用一个运行时技能，随后重新请求技能列表
- **THEN** 该技能在列表中仍为停用状态

#### Scenario: 启用后恢复

- **WHEN** 对同一个技能执行启用
- **THEN** 该技能回到运行时提供的原始定义，停用标记被清除
